# Albatross.CommandLine — CLI Development Guide

This skill documents how to correctly build .NET CLI applications using the Albatross.CommandLine
family of packages (v9). Follow these patterns precisely — the library uses Roslyn source generators,
so the conventions are load-bearing.

**Full documentation:** https://rushuiguan.github.io/commandline/

**The v9 stance: the library provides capabilities, not policies.** It adds no global options, no
console logging and no output format on your behalf. `stdout`/`stderr` belong to the command;
logging is opt-in and goes to a file; structured output is opt-in through the Outputs package.

---

## Packages

| Package | Purpose | When to use |
|---------|---------|-------------|
| `Albatross.CommandLine` | Core runtime: `CommandHost`, attributes, `BaseHandler<T>`. **Bundles the source generator** (generates `AddCommands`, `RegisterCommands`) | Always |
| `Albatross.CommandLine.Defaults` | `appsettings.json` config + file-based Serilog logging via `WithDefaults()` | Apps that want config and logging |
| `Albatross.CommandLine.Outputs` | `CommandOutput` envelope, JSON `Print`, `--compact`, `GlobalErrorHandler` | Apps that print results (most do) |
| `Albatross.CommandLine.Inputs` | Pre-built validated `Option`/`Argument` types for files, directories and more | When you need those inputs |
| `Albatross.CommandLine.CodeAnalysis` | Roslyn analyzers for best practices | Optional |

Do **not** reference `Albatross.CommandLine.CodeGen` — the generator ships inside the core package,
and a separate reference loads it twice.

Install (v9 is published on the prerelease channel until System.CommandLine v3 reaches GA; keep every
`Albatross.CommandLine.*` package on the same version):
```
dotnet new console -n MyCliApp --framework net10.0
dotnet add package Albatross.CommandLine --prerelease
dotnet add package Albatross.CommandLine.Defaults --prerelease   # optional
dotnet add package Albatross.CommandLine.Outputs --prerelease    # optional
dotnet add package Albatross.CommandLine.Inputs --prerelease     # optional
```

Always use `--framework net10.0` when creating new CLI projects.

## Bootstrap (Program.cs)

```csharp
using Albatross.CommandLine;
using Albatross.CommandLine.Defaults;  // if using Defaults
using Albatross.CommandLine.Outputs;   // if using Outputs
using Albatross.Config;
using Microsoft.Extensions.DependencyInjection;
using MyApp.AutoGenerated;   // generated AddCommands()/RegisterCommands() live in <RootNamespace>.AutoGenerated
using System.CommandLine;

namespace MyApp {
    internal class Program {
        static async Task<int> Main(string[] args) {
            var appPath = new EnterpriseApplicationPath("MyApp", "LogDirectory", "DataDirectory");
            appPath.Init();
            await using var host = new CommandHost("My App Name")
                .RegisterServices((result, services) => RegisterServices(result, services, appPath))
                .AddCommands()                      // generated — won't compile until first [Verb] exists
                .Parse(args)
                .WithDefaults(appPath.ConfigRoot)   // optional: config + file logging
                .Build();
            return await host.InvokeAsync();
        }

        static void RegisterServices(ParseResult result, IServiceCollection services, IApplicationPath appPath) {
            services.AddSingleton(appPath);
            services.AddSingleton<ICommandErrorHandler, GlobalErrorHandler>(); // optional, from Outputs
            services.RegisterCommands(); // generated — registers all handlers and params classes
            services.AddSingleton<IMyService, MyService>();
        }
    }
}
```

**Order:** `RegisterServices` → `AddCommands` → `Parse` → `WithDefaults` → `Build`. The command tree
must be complete before `Parse()`; `RegisterServices` runs lazily at `Build()`, so it can come first.
The `IApplicationPath` is optional — without one, `WithDefaults()` logs to a `log` folder beside the
binary and reads `appsettings.json` from the application directory.

**Namespace of the generated extensions:** `AddCommands()` and `RegisterCommands()` are generated into
`<RootNamespace>.AutoGenerated` (e.g. `MyApp.AutoGenerated`). Add a `using` for that namespace in any file
that calls them. Replace `MyApp` with your project's `RootNamespace` (defaults to the project/assembly name).

**Conditional registration:** `RegisterServices` receives the `ParseResult`, so services needed by only
one command can be registered for that command alone:
`if (result.CommandResult.Command.GetCommandKey().StartsWith("csharp ")) { ... }`.

## Critical Requirements

**All params and handler classes must be in a namespace.** The source generator fails with
`Invalid namespace identifier: ''` if files use top-level declarations without a namespace.
Always wrap classes in `namespace YourApp { ... }`.

**`ParseResult` is in `System.CommandLine`**, not `System.CommandLine.Parsing`:
```csharp
using System.CommandLine; // correct
```

## Defining a Command

Every command needs two things: a **params class** (decorated with `[Verb<THandler>]`) and a
**handler class** (extends `BaseHandler<T>`). The source generator wires them together.

### 1. Params Class

```csharp
using Albatross.CommandLine.Annotations;

namespace MyApp {
    [Verb<HelloWorldHandler>("hello", Description = "Say hello to someone")]
    public record class HelloWorldParams {
        [Argument(Description = "The name to greet")]
        public required string Name { get; init; }

        // DefaultToInitializer = true is required to use the property initializer as a default.
        // Without it, non-nullable value types (int, bool, etc.) are treated as required.
        [Option(DefaultToInitializer = true, Description = "Number of times to repeat")]
        public int Count { get; init; } = 1;

        [Option("--shout", "-s", Description = "Use uppercase")]
        public bool Shout { get; init; }
    }
}
```

### 2. Handler Class

```csharp
using Albatross.CommandLine;
using Microsoft.Extensions.Logging;
using System.CommandLine;

namespace MyApp {
    public class HelloWorldHandler : BaseHandler<HelloWorldParams> {
        private readonly ILogger<HelloWorldHandler> logger;

        public HelloWorldHandler(
            ParseResult result,
            HelloWorldParams parameters,
            ILogger<HelloWorldHandler> logger) : base(result, parameters) {
            this.logger = logger;
        }

        public override async Task<int> InvokeAsync(CancellationToken cancellationToken) {
            var greeting = parameters.Shout
                ? $"HELLO, {parameters.Name.ToUpper()}!"
                : $"Hello, {parameters.Name}!";

            for (int i = 0; i < parameters.Count; i++) {
                Writer.WriteLine(greeting);
            }
            logger.LogInformation("Greeted {Name}", parameters.Name);
            return 0; // exit code
        }
    }
}
```

`BaseHandler<T>` gives you:
- `parameters` — the typed params instance
- `result` — the raw `ParseResult`
- `Writer` — the invocation's output `TextWriter` (stdout by default; useful for testability)

Plain text through `Writer` is fine for simple commands. For a command that returns data, print it
through the Outputs package instead (see **Output** below). Either way, stdout carries only the
result — progress notes and diagnostics go to `ILogger`.

## Arguments vs Options

| | Argument | Option |
|--|--|--|
| Syntax | Positional (no name) | Named (`--flag value`) |
| Order | Matters (declaration order) | Any order |
| Attribute | `[Argument]` | `[Option]` |
| Required by default | `required` keyword | `required` keyword |

**Required/optional rules:**
- Non-nullable + `required` keyword → required
- Nullable (`string?`, `int?`) → optional
- Boolean → optional (flag, defaults false)
- Collection → optional
- `[Option(DefaultToInitializer = true)]` with property initializer → optional with default

## Subcommand Hierarchy

Use spaces in the verb name to create parent→child relationships:

```csharp
// Parent command (no handler needed)
[Verb("config", Description = "Configuration commands")]
public record class ConfigParams { }

// Children
[Verb<ConfigGetHandler>("config get", Description = "Get a config value")]
public record class ConfigGetParams {
    [Argument]
    public required string Key { get; init; }
}

[Verb<ConfigSetHandler>("config set", Description = "Set a config value")]
public record class ConfigSetParams {
    [Argument]
    public required string Key { get; init; }

    [Argument]
    public required string Value { get; init; }
}
```

Usage: `myapp config get SomeKey`, `myapp config set SomeKey somevalue`

## Assembly-Level Verbs

When you don't want a dedicated params class (e.g., for using built-in handler types), declare
the verb at assembly level:

```csharp
// In Verbs.cs or GlobalUsings.cs
[assembly: Verb<MyParamsClass, MyHandler>("command-name", Description = "...")]
```

The two-type `Verb<TParams, THandler>` form is valid **only** at assembly level; on a class it fails
with `CS0592`. This is especially useful with `Albatross.EFCore.Admin` handlers — see the alba-efcore skill.

## Naming Conventions

| Element | Pattern | Example |
|---------|---------|---------|
| Params class | `*Params` suffix | `BackupParams` |
| Generated command class | Remove `Params`, add `Command` | `BackupCommand` |
| Handler class | `*Handler` or `*CommandHandler` | `BackupHandler` |
| Properties → CLI names | kebab-case | `OutputFolder` → `--output-folder` |

The generator derives option and argument names from property names automatically.

## Output (Albatross.CommandLine.Outputs)

A command's stdout is its result: it gets piped to `jq`, captured by scripts and fed to AI tooling.
Outputs makes that result a stable JSON contract.

```csharp
using Albatross.CommandLine.Annotations;
using Albatross.CommandLine.Outputs;

[Verb<GetWidgetsHandler>("get widgets")]
public record class GetWidgetsParams {
    [UseOption<CompactOption>]
    public bool Compact { get; init; }
}

public class GetWidgetsHandler : BaseHandler<GetWidgetsParams> {
    readonly IWidgetService service;

    public GetWidgetsHandler(ParseResult result, GetWidgetsParams parameters, IWidgetService service)
        : base(result, parameters) {
        this.service = service;
    }

    public override async Task<int> InvokeAsync(CancellationToken cancellationToken) {
        var widgets = await service.GetAll(cancellationToken);
        widgets.Print(parameters.Compact);
        return 0;
    }
}
```

- **`value.Print(compact, stderr: false)`** — objects and arrays print as indented, colored JSON on a
  terminal (ANSI is stripped automatically when piped); `--compact` gives single-line JSON; scalars
  print raw so scripts can capture them, formatted as JSON values (`true`, `2026-11-16`), not `ToString()`.
- **`await value.PrintAsync(compact, cancellationToken)`** — same output decisions, no color. Prefer it
  for large or unbounded results and for output a program parses: it writes in slices and stops on
  Ctrl+C (throwing `OperationCanceledException` — let it propagate), and its indented output is always
  valid JSON. `Print`'s indented output goes through Spectre, which wraps long lines even when
  redirected and can break a JSON string.
- **Commands that report an outcome rather than data** — `result.PrintSuccess("deleted widget 42")`,
  `result.PrintSuccessWithData(message, data)`, and `return result.PrintError(message, errorMessage)`.
  These emit a `CommandOutput` envelope (`command`, `message`, `exitCode`, `errors`, `data`) — success
  to stdout, errors to stderr — and call `result.IsCompact()`, which is safe when the command does not
  declare `--compact`.
- **Errors** — register `GlobalErrorHandler` as the `ICommandErrorHandler` (see Bootstrap) and let
  exceptions propagate instead of catching and printing them. It writes the same `CommandOutput`
  envelope to stderr with an `errors[]` array, and returns exit code 1 (130 for Ctrl+C).
- **`--compact` is never auto-registered.** Apply `CompactOption` per command, or put it on a shared
  base params record that data commands inherit (a params class can inherit a `record` base only if it
  is itself a `record class`).
- **Serialization is `System.Text.Json`** (read-only `Extensions.CompactSerializerOptions` /
  `FormattedSerializerOptions`: camelCase, enums as names, nulls dropped, defaults and empty collections kept). Customize result types with
  `System.Text.Json.Serialization` attributes such as `[JsonPropertyName]` and `[JsonIgnore]` —
  Newtonsoft attributes are ignored.
- **No built-in query option.** The library always emits the full result; callers shape it with an
  external tool: `myapp get widgets --compact | jq -r '.[].name'`.

## Defaults Package (Logging & Config)

Add `Albatross.CommandLine.Defaults` for configuration and file-based Serilog logging:

```csharp
// Combined (recommended)
.Parse(args)
.WithDefaults(appPath.ConfigRoot)
.Build()

// Or separately:
.Parse(args)
.WithConfig(appPath.ConfigRoot)   // appsettings.json + appsettings.{DOTNET_ENVIRONMENT}.json + env vars
.WithSerilog()                    // file-based Serilog logging
.Build()
```

**What `WithConfig(configDirectory)` does:**
- Loads `appsettings.json` and `appsettings.{DOTNET_ENVIRONMENT}.json` (both optional) from
  `configDirectory` — which **replaces** the base path; it defaults to the application directory
- Adds environment variables
- Registers `IConfiguration`, `EnvironmentSetting`, `ProgramSetting`, `IHostEnvironment`
- Takes an optional `Action<IConfiguration, IServiceCollection>` for config-dependent registrations

**What `WithSerilog()` does:**
- Writes a daily-rolling file `{IApplicationPath.LogRoot}/{assembly}-.log`. **There is no console
  sink** — stdout/stderr stay free for the command's output
- Uses the registered `IApplicationPath`; without one, falls back to `DefaultApplicationPath`
  (a `log` folder under the application directory)
- Baseline level is `Information`. Tune it — and add per-namespace overrides or extra sinks — in a
  `Serilog` section of `appsettings.json`, e.g. `"Serilog": { "MinimumLevel": { "Default": "Debug" } }`

Without `WithDefaults()`/`WithSerilog()` there is no logging provider at all: `ILogger<T>` still
resolves but writes nowhere. `CommandHost` also loads no configuration on its own — an app that reads
`IConfiguration` must call `WithConfig()` or `WithDefaults()`.

**There is no `--verbosity` option.** Logging level is configuration, not a flag. If an app genuinely
wants a cross-cutting flag, add a recursive option to the root command **before** `Parse()`:

```csharp
var verbosity = new Option<LogLevel>("--verbosity", "-v") { Recursive = true, DefaultValueFactory = _ => LogLevel.Information };
host.CommandBuilder.RootCommand.Options.Add(verbosity);
```

**Inject `IConfiguration` in a handler:**

```csharp
public class MyHandler : BaseHandler<MyParams> {
    private readonly IConfiguration config;

    public MyHandler(ParseResult result, MyParams parameters, IConfiguration config)
        : base(result, parameters) {
        this.config = config;
    }

    public override Task<int> InvokeAsync(CancellationToken token) {
        var connStr = config.GetConnectionString("Default");
        return Task.FromResult(0);
    }
}
```

> **Note:** `Albatross.CommandLine.Defaults` uses the latest package versions (not .NET Standard
> 2.1). For strict version compatibility, configure logging/config manually instead.

## Reusable Option and Argument Classes

Define once, use across many commands. The class must follow the required constructor signature.

### Reusable Option

```csharp
[DefaultNameAliases("--input-dir", "--in", "-i")]
public class InputDirectoryOption : Option<DirectoryInfo> {
    // Constructor signature is required by the source generator
    public InputDirectoryOption(string name, params string[] aliases) : base(name, aliases) {
        Description = "Specify an existing input directory";
        Validators.Add(result => {
            if (result.GetValue(this) is DirectoryInfo dir && !dir.Exists)
                result.AddError($"Directory {dir.FullName} does not exist");
        });
    }
}
```

### Reusable Argument

```csharp
public class InputDirectoryArgument : Argument<DirectoryInfo> {
    // Constructor signature is required by the source generator
    public InputDirectoryArgument(string name) : base(name) {
        Description = "Specify an existing input directory";
        Validators.Add(result => {
            if (result.GetValue(this) is DirectoryInfo dir && !dir.Exists)
                result.AddError($"Directory {dir.FullName} does not exist");
        });
    }
}
```

### Using Reusable Parameters

```csharp
[Verb<BackupHandler>("backup")]
public record class BackupParams {
    // Uses default names from [DefaultNameAliases] → --input-dir, --in, -i
    [UseOption<InputDirectoryOption>]
    public required DirectoryInfo Source { get; init; }

    // UseCustomName = true → derives name from property → --destination
    [UseOption<InputDirectoryOption>(UseCustomName = true)]
    public required DirectoryInfo Destination { get; init; }

    [UseArgument<InputDirectoryArgument>]
    public required DirectoryInfo ExtraDir { get; init; }
}
```

## Built-in Inputs (Albatross.CommandLine.Inputs)

Pre-built reusable types — no need to write your own for common scenarios:

| Type | What it does |
|------|-------------|
| `InputFileOption` / `InputFileArgument` | Validates file exists |
| `InputDirectoryOption` / `InputDirectoryArgument` | Validates directory exists |
| `OutputFileOption` | For output file paths |
| `OutputDirectoryOption` / `OutputDirectoryArgument` | For output directory paths |
| `OutputDirectoryWithAutoCreateOption` | Auto-creates directory if missing |
| `TimeZoneOption` | For timezone name inputs |
| `ConfirmOption` | `--confirm`/`-c`; prompts for confirmation before proceeding (defaults to `true`) |
| `TrackerOption` | Tracker file that records processed items so a rerun skips them |

```csharp
[Verb<ProcessHandler>("process")]
public record class ProcessParams {
    [UseOption<InputFileOption>]
    public required FileInfo InputFile { get; init; }

    [UseOption<OutputDirectoryWithAutoCreateOption>]
    public required DirectoryInfo OutputDir { get; init; }
}
```

## Option Pre-processing and Validation (OptionHandler)

Run async validation (DB calls, API checks) before the command handler executes.
Attach an `[OptionHandler]` to a reusable option class. To stop the command, either record an error
on the context or throw — both skip the command handler and are reported through the registered
`ICommandErrorHandler` with `ErrorSource.OptionHandler`:

```csharp
[DefaultNameAliases("--api-key", "-k")]
[OptionHandler<ApiKeyOption, ApiKeyValidator>]
public class ApiKeyOption : Option<string> {
    public ApiKeyOption(string name, params string[] aliases) : base(name, aliases) {
        Description = "The API key";
    }
}

public class ApiKeyValidator : IAsyncOptionHandler<ApiKeyOption> {
    private readonly IAuthService auth;
    private readonly ICommandContext context;

    public ApiKeyValidator(IAuthService auth, ICommandContext context) {
        this.auth = auth;
        this.context = context;
    }

    public async Task InvokeAsync(ApiKeyOption option, ParseResult result,
        CancellationToken cancellationToken) {
        var key = result.GetValue(option);
        if (!await auth.IsValidAsync(key, cancellationToken)) {
            // Short-circuit: command handler will not run
            context.SetInputActionError(new Error(ErrorSource.OptionHandler, option.Name, "Invalid API key", null));
        }
    }
}
```

## Input Transformation (OptionHandler with output type)

Transform a simple CLI input (e.g., string ID) into a rich object before the handler runs. Prefer this
over passing data through `ICommandContext`:

```csharp
[DefaultNameAliases("--instrument", "-i")]
[OptionHandler<InstrumentOption, InstrumentOptionHandler, InstrumentSummary>]
public class InstrumentOption : Option<string> {
    public InstrumentOption(string name, params string[] aliases) : base(name, aliases) {
        Description = "Instrument identifier";
    }
}

public class InstrumentOptionHandler : IAsyncOptionHandler<InstrumentOption, InstrumentSummary> {
    private readonly InstrumentService svc;
    public InstrumentOptionHandler(InstrumentService svc) { this.svc = svc; }

    public async Task<OptionHandlerResult<InstrumentSummary>> InvokeAsync(
        InstrumentOption option, ParseResult result, CancellationToken ct) {
        var id = result.GetValue(option);
        if (string.IsNullOrEmpty(id)) return new OptionHandlerResult<InstrumentSummary>();
        var summary = await svc.GetSummaryAsync(id, ct);
        return new OptionHandlerResult<InstrumentSummary>(summary);
    }
}

// Property type is the *output* type, not the raw CLI type
[Verb<PriceHandler>("get-price")]
public record class GetPriceParams {
    [UseOption<InstrumentOption>]
    public required InstrumentSummary Instrument { get; init; }
}
```

## Mutually Exclusive Parameter Sets

When several commands share logic but have different options, derive their params classes from a
shared base, name that base in `BaseParamsClass`, and let one handler take the base type:

```csharp
public abstract record class CodeGenParams {
    [Option]
    public required FileInfo ProjectFile { get; init; }
}

[Verb<CodeGenHandler>("codegen csharp", BaseParamsClass = typeof(CodeGenParams))]
public record class CSharpCodeGenParams : CodeGenParams {
    [Option]
    public required string Namespace { get; init; }
}

[Verb<CodeGenHandler>("codegen typescript", BaseParamsClass = typeof(CodeGenParams))]
public record class TypeScriptCodeGenParams : CodeGenParams {
    [Option]
    public bool StrictMode { get; init; }
}

public class CodeGenHandler : BaseHandler<CodeGenParams> {
    public CodeGenHandler(ParseResult result, CodeGenParams parameters) : base(result, parameters) { }

    public override async Task<int> InvokeAsync(CancellationToken ct) {
        return parameters switch {
            CSharpCodeGenParams cs => await GenerateCSharp(cs, ct),
            TypeScriptCodeGenParams ts => await GenerateTypeScript(ts, ct),
            _ => throw new NotSupportedException($"Unsupported parameters type: {parameters.GetType()}")
        };
    }
}
```

The generator registers `CodeGenParams` with a factory that builds the derived class matching the
invoked command.

## Command Customization

Generated command classes are `partial`. Use the `Initialize()` partial method for custom setup:

```csharp
public partial class MyCommand {
    partial void Initialize() {
        // Access generated Option_* and Argument_* properties
        Option_OutputFile.Validators.Add(result => {
            if (result.GetValue(Option_OutputFile) is FileInfo file && file.Exists)
                result.AddError($"{file.FullName} already exists");
        });
        Argument_Name.DefaultValueFactory = _ => "World";
    }
}
```

## Execution Pipeline

```
Parse CLI Arguments
      ↓
Create DI Scope
      ↓
Option PreActions (IAsyncOptionHandler — validation/transformation, in declaration order)
      ↓ (stop if any option handler recorded an error or threw)
Command Action (IAsyncCommandHandler.InvokeAsync)
      ↓
Errors (option handler, service resolution, command handler, cancellation) → ICommandErrorHandler
      ↓
Dispose DI Scope
```

Every failure is captured as an `Error` (`Source`, `Symbol`, `Message`, `Exception?`) and passed to the
registered `ICommandErrorHandler`, which decides the exit code (`GlobalErrorHandler`: 1, or 130 for
cancellation). Errors are logged where they are caught.

## DI Services Available in Handlers

All of these can be injected into any handler constructor:

| Service | Description |
|---------|-------------|
| `ParseResult` | Raw parse result from System.CommandLine |
| `T parameters` | The typed params class instance |
| `ICommandContext` | Command key, values shared between option handlers and the command handler, input-action errors |
| `ILogger<T>` | Logging (writes to a file with `WithDefaults()`/`WithSerilog()`; nowhere without) |
| `IConfiguration` | App configuration (requires `WithConfig()` or `WithDefaults()`) |
| Any custom service | Anything registered in `RegisterServices` |

## Viewing Generated Code

To inspect what the source generator produces, add to your `.csproj`:

```xml
<PropertyGroup>
    <EmitCompilerGeneratedFiles>true</EmitCompilerGeneratedFiles>
    <CompilerGeneratedFilesOutputPath>$(BaseIntermediateOutputPath)generated</CompilerGeneratedFilesOutputPath>
</PropertyGroup>
```

Generated files appear in `obj/generated/`. The generator creates:
- `{CommandName}Command.g.cs` — partial command class with `Option_*` and `Argument_*` properties
- `CodeGenExtensions.g.cs` — `RegisterCommands()` and `AddCommands()` methods, generated into the `<RootNamespace>.AutoGenerated` namespace

## Quick Checklist: Adding a New Command

1. Create a params class with `[Verb<THandler>("verb-name")]`
2. Add properties with `[Option]` or `[Argument]` (and `[UseOption<CompactOption>]` if it prints data)
3. Create handler class extending `BaseHandler<TParams>`
4. Implement `override Task<int> InvokeAsync(CancellationToken ct)`; print the result with `Print`
5. Build — the source generator regenerates `RegisterCommands()` and `AddCommands()` automatically
6. Test: `dotnet run -- verb-name [args] [options]` — and check that stdout holds only the result
